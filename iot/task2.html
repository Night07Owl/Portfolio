01

Overview

// OBJECTIVE & SUMMARY

The objective of this assignment is to extend hardware control beyond local Wi-Fi networks by establishing a secure, persistent MQTT connection between an ESP32 and the Adafruit IO cloud ecosystem.

Local web servers (as implemented in Task 1) require port forwarding or dynamic DNS to be accessed outside the immediate building. MQTT solves this limitation through a central cloud broker. In this assignment, we provisioned an Adafruit IO account, established an MQTT topic feed, designed an interactive cloud dashboard with toggle controls and live indicator widgets, and configured the ESP32 as an MQTT subscriber. When the user flips a switch on the Adafruit IO web or mobile dashboard from anywhere in the world, the broker instantly pushes a packet to the ESP32 to switch the LED state in milliseconds.

02

Concepts (In My Own Words)

// FORGE RULE #1: OWN WORDS > COPY-PASTE

What is MQTT?

MQTT (Message Queuing Telemetry Transport) is an extremely compact messaging protocol created specifically for battery-powered microcontrollers and unreliable wireless links. Unlike bulky HTTP with large text headers, MQTT packets can be as tiny as 2 bytes, keeping network traffic and power consumption near zero.

Publisher, Broker & Subscriber

Instead of direct peer-to-peer connections, MQTT uses a central post office called the Broker (Adafruit IO). A Publisher (e.g. the Dashboard) sends a message to a topic. The Subscriber (ESP32) listens to that topic. The publisher and subscriber never know each other's IP address.

Feeds & Topics

Topics act like specific channels or inbox addresses. In Adafruit IO, topics are organized hierarchically as username/feeds/feed-name. Devices subscribe to this exact path to receive real-time updates whenever new payload data is written to the feed.

Implementation & Source Code

// ESP32 MQTT FIRMWARE
ESP32_AdafruitIO_MQTT.ino 
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

#define WLAN_SSID       "YOUR_WIFI_SSID"
#define WLAN_PASS       "YOUR_WIFI_PASSWORD"
#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883
#define AIO_USERNAME    "YOUR_AIO_USERNAME"
#define AIO_KEY         "YOUR_AIO_KEY"

const int ledPin = 2;

WiFiClient client;
Adafruit_MQTT_Client mqtt(&client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);

// Set up subscription to Adafruit IO feed
Adafruit_MQTT_Subscribe ledFeed = Adafruit_MQTT_Subscribe(&mqtt, AIO_USERNAME "/feeds/led-control");

void MQTT_connect();

void setup() {
  Serial.begin(115200);
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);

  Serial.print("Connecting to Wi-Fi...");
  WiFi.begin(WLAN_SSID, WLAN_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nWi-Fi Connected!");

  // Subscribe to LED feed
  mqtt.subscribe(&ledFeed);
}

void loop() {
  MQTT_connect();

  // Read incoming subscription packets with 5000ms timeout
  Adafruit_MQTT_Subscribe *subscription;
  while ((subscription = mqtt.readSubscription(5000))) {
    if (subscription == &ledFeed) {
      Serial.print("Payload Received: ");
      Serial.println((char *)ledFeed.lastread);

      if (strcmp((char *)ledFeed.lastread, "ON") == 0 || strcmp((char *)ledFeed.lastread, "1") == 0) {
        digitalWrite(ledPin, HIGH);
      }
      if (strcmp((char *)ledFeed.lastread, "OFF") == 0 || strcmp((char *)ledFeed.lastread, "0") == 0) {
        digitalWrite(ledPin, LOW);
      }
    }
  }

  // Keep-alive ping every loop cycle
  if (!mqtt.ping()) {
    mqtt.disconnect();
  }
}

void MQTT_connect() {
  int8_t ret;
  if (mqtt.connected()) return;

  Serial.print("Connecting to MQTT Broker... ");
  uint8_t retries = 3;
  while ((ret = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(ret));
    Serial.println("Retrying MQTT connection in 5 seconds...");
    mqtt.disconnect();
    delay(5000);
    retries--;
    if (retries == 0) {
      while (1); // Wait for WDT reset
    }
  }
  Serial.println("MQTT Connected!");
}

Challenges & Solutions Encountered

// FORGE RULE #2: SHOW THE FAILURE, NOT JUST FIX
FAILURE #1
Frequent Disconnections with Error Code -4 (Connection Lost)
Root Cause Analysis

The Adafruit IO MQTT Broker expects a ping packet every 60 seconds. A blocking delay(2000) in the main loop prevented the client library from dispatching background keep-alive ping packets in time, causing the cloud broker to disconnect the ESP32.

Solution Implemented

Eliminated all blocking delay() statements in favor of non-blocking millis() timer loops, and ensured mqtt.ping() is called periodically with an automatic reconnect helper.

FAILURE #2
Adafruit IO Free-Tier Rate Limiting Throttling
Root Cause Analysis

During initial testing, the ESP32 was publishing its status on every single loop pass (~100 times per second). Adafruit IO's free limit allows a maximum of 30 data points per minute, resulting in immediate 429 Throttle bans.

Solution Implemented

Implemented state-change filtering: the ESP32 only publishes when currentState != previousState, ensuring zero wasted packets and 100% rate-limit compliance.
