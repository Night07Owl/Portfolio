Objective

// TASK 4 CORE OBJECTIVE

To develop and deploy a login-protected web dashboard using Firebase before connecting the hardware.

  • Establish the software infrastructure for the Smart IoT Monitoring System using Google Firebase BaaS.
  • Create a Firebase cloud project and register a web application to acquire production API configurations.
  • Install and configure the Firebase CLI tools to initialize local files for Firebase Hosting deployment.
  • Deploy the web application to Firebase Hosting, securing a globally accessible, high-performance HTTPS URL.

02

Problem Being Addressed

// SOFTWARE INFRASTRUCTURE GAPS SOLVED
  • Local Subnet Confinement: Standalone web servers hosted directly on embedded chips restrict access to users connected to the exact same Wi-Fi router, preventing worldwide remote monitoring.
  • Absence of Identity & Access Management: Basic microcontrollers lack authenticated user access, exposing actuators to arbitrary, unverified triggers from anyone on the network.
  • High-Latency Polling Bottlenecks: Traditional HTTP polling strains client and server resources, while Firebase WebSockets provide instant, sub-50ms reactive updates.
  • Lack of Structured Database Design: Deploying hardware before establishing a well-defined cloud schema causes data ingestion errors, schema drift, and lost sensor records. Task 4 eliminates this by establishing the complete database blueprint first.
03

Task 4 Scope & Architectural Focus

// SOFTWARE-FIRST METHODOLOGY

Task 4 focused exclusively on building the software infrastructure for the Smart IoT Monitoring System. A Firebase project was created to provide hosting, user authentication, and real-time database services. By decoupling software creation and cloud deployment from physical hardware wiring, the interface, authentication gateway, and database contracts were validated and deployed to production first.

Outcome: A fully deployed Firebase web application with login functionality and a prepared database structure. The dashboard was ready for hardware integration, although the sensor values were still placeholders.

Foundational Cloud Computing & Database Concepts

// THEORETICAL & ARCHITECTURAL MASTERY
☁️
FOUNDATION

What is Cloud Computing?

The on-demand delivery of IT resources (computing power, storage, databases, and networking) over the internet with pay-as-you-go pricing, replacing on-premise hardware infrastructure.

🏢
PLATFORM

What is a Cloud Platform?

A unified suite of cloud services provided by vendors (e.g., Google Cloud / Firebase, AWS, Azure) enabling developers to build, deploy, manage, and scale applications without maintaining physical datacenters.

🗄️
STORAGE

What is a Database?

An organized collection of structured data stored electronically. While relational databases use tables and SQL, Firebase Realtime Database utilizes a NoSQL JSON document tree optimized for millisecond-scale synchronizations.

🔥
BAAS ENGINE

Firebase Realtime Database

A cloud-hosted NoSQL JSON database where data is synchronized in real time across all connected clients via persistent full-duplex WebSockets, remaining available even during transient offline conditions.

📊
INTERFACE

What is a Cloud-Based Dashboard?

A centralized, web-accessible graphical user interface that aggregates real-time telemetry, visualizes system performance metrics, and enables authenticated operators to dispatch control commands to connected assets from any browser.

🛡️
SECURITY

Authentication & Login Purpose

The process of verifying the digital identity of a user attempting access. A login system ensures that only authorized administrators can control physical appliances or inspect sensitive environmental telemetry.

MODELS

Cloud Service Models: IaaS vs PaaS vs SaaS vs BaaS

// CLOUD ARCHITECTURAL TIERS
Model Tier Full Form What the Provider Manages What the Developer Manages IoT System Context

SECURITY

Difference Between Authentication and Authorization

// ACCESS CONTROL BOUNDARIES

🔑 Authentication (AuthN) — "Who are you?"

Verifies the digital identity of a user or device. In Task 4, this is handled by Firebase Authentication using verified email and password credentials (trialusep@gmail.com). It produces a validated JSON Web Token (JWT).

🛡️ Authorization (AuthZ) — "What can you do?"

Determines permissions and access levels granted to an authenticated entity. In Task 4, this is enforced by Firebase Realtime Database Security Rules (".read" and ".write"), restricting read/write capabilities based on user token status.

Realtime Database Setup & Prepared Schema Structure

// 4-NODE NOSQL ARCHITECTURE

In accordance with the software specification, the Realtime Database was initialized with four distinct top-level nodes: current, history, sensors, and settings. Before connecting physical hardware in Task 5, these nodes were populated with structured placeholder values to facilitate complete front-end data binding, dashboard state rendering, and authentication testing.

/current

Holds active telemetry values (temperature, humidity, light) and actuator status (bulb ON/OFF). Seeded with placeholder readings (e.g. 25.0°C, 50% RH).

/history

Chronological collection of time-series telemetry records indexed by push keys or timestamps for analytics, trends, and CSV file exports.

/sensors

Metadata registry specifying connected sensor modules, pin assignments (DHT11 on GPIO 4, LDR on GPIO 34), calibration coefficients, and units.

/settings

Operational configuration parameters: system operating mode ("manual" vs "automatic"), relay manual state, and LDR light threshold.

onAuthStateChanged(auth, (user) => {

// --- 3. REALTIME DATABASE STATE SYNCHRONIZATION ---
function initializeDatabaseListeners() {
  // Listen to /current telemetry updates (sub-50ms reactive delta)
  const currentRef = ref(db, "current");
  onValue(currentRef, (snapshot) => {
    const data = snapshot.val();
    if (!data) return;

    // Update Temperature Display
    if (data.temperature !== undefined) {
      tempValueEl.textContent = `${Number(data.temperature).toFixed(1)} °C`;
    }

    // Update Humidity Display
    if (data.humidity !== undefined) {
      humidityValueEl.textContent = `${Number(data.humidity).toFixed(1)} %`;
    }

    // Update Ambient Light Display
    if (data.ambientLight !== undefined || data.ldr !== undefined) {
      const lightVal = data.ambientLight ?? data.ldr;
      ldrValueEl.textContent = `${lightVal} ADC`;
    }

    // Update Bulb Actuator Visual Indicator
    const isBulbOn = data.bulbStatus ?? data.bulb;
    if (isBulbOn) {
      bulbStatusEl.textContent = "ON";
      bulbStatusEl.className = "state-badge badge-on";
      bulbIconEl.classList.add("bulb-lit");
    } else {
      bulbStatusEl.textContent = "OFF";
      bulbStatusEl.className = "state-badge badge-off";
      bulbIconEl.classList.remove("bulb-lit");
    }
  });

  // Listen to /settings for mode and threshold synchronization
  const settingsRef = ref(db, "settings");
  onValue(settingsRef, (snapshot) => {
    const settings = snapshot.val();
    if (!settings) return;

    if (settings.operatingMode) {
      modeSelect.value = settings.operatingMode;
      toggleManualButtonsState(settings.operatingMode === "manual");
    }

    if (settings.ldrLightThreshold !== undefined) {
      thresholdSlider.value = settings.ldrLightThreshold;
      thresholdDisplay.textContent = settings.ldrLightThreshold;
    }
  });
}

// Mode Selection Change Handler
modeSelect.addEventListener("change", (e) => {
  const selectedMode = e.target.value;
  update(ref(db, "settings"), { operatingMode: selectedMode });
  toggleManualButtonsState(selectedMode === "manual");
});

// Manual Bulb ON Handler
btnBulbOn.addEventListener("click", () => {
  update(ref(db, "settings"), { manualBulbOverride: true });
});

// Manual Bulb OFF Handler
btnBulbOff.addEventListener("click", () => {
  update(ref(db, "settings"), { manualBulbOverride: false });
});

// Threshold Slider Handler
thresholdSlider.addEventListener("input", (e) => {
  thresholdDisplay.textContent = e.target.value;
});
thresholdSlider.addEventListener("change", (e) => {
  update(ref(db, "settings"), { ldrLightThreshold: Number(e.target.value) });
});

function toggleManualButtonsState(isManual) {
  btnBulbOn.disabled = !isManual;
  btnBulbOff.disabled = !isManual;
  btnBulbOn.style.opacity = isManual ? "1" : "0.45";
  btnBulbOff.style.opacity = isManual ? "1" : "0.45";
}

Problems Encountered & Software Solutions

// CLOUD & FRONT-END TROUBLESHOOTING
⚠️

Problem 1 — Firebase CLI Deployment Authorization Expiry

Issue: Running firebase deploy resulted in Error: Failed to authenticate, token expired, halting deployment pipelines to Firebase Hosting.

Fix: Re-authenticated the environment using firebase login --reauth in the local shell, refreshing OAuth refresh tokens and restoring seamless continuous deployment.
⚠️

Problem 2 — Single-Page App (SPA) Direct URL Routing 404s

Issue: Direct visits or browser refreshes on internal dashboard routes triggered default HTTP 404 errors on Firebase Hosting edge servers.

Fix: Configured "rewrites": [ { "source": "**", "destination": "/index.html" } ] in firebase.json, delegating all URL routing to client-side JavaScript.
⚠️

Problem 3 — Dashboard Manual/Auto Button Conflict & Race Condition

Issue: Operators could trigger manual ON/OFF toggle buttons while the system mode was in Automatic, creating potential race conditions once connected to hardware.

Fix: In app.js, dynamically disabled manual ON/OFF buttons (opacity: 0.45, disabled: true) whenever the mode dropdown is set to Automatic, guaranteeing conflict-free operation.
⚠️

Problem 4 — Firebase Modular SDK CORS and AdBlocker Interference

Issue: Certain browser privacy extensions blocked CDN scripts loaded from gstatic.com, causing silent authentication failures.

Fix: Handled initialization exceptions gracefully with user alerts and verified Content Security Policy (CSP) headers in hosting configuration to ensure safe module loading.
