01

Overview

// OBJECTIVE & SUMMARY

The objective of this capstone assignment is to synthesize all previous stations into a self-governing, industrial-style IoT telemetry and automated control station.

While monitoring real-time sensor metrics is valuable, real-world deployments require historical telemetry records and autonomous closed-loop control. In this final assignment, we developed a smart lighting and climate monitoring system that operates in two user-selectable modes: Manual Mode (user controls the relay directly via the dashboard) and Automatic Mode (the ESP32 continuously assesses ambient LDR light readings against a calibrated hysteresis threshold to toggle lighting automatically). Simultaneously, the ESP32 logs timestamped sensor snapshots (temperature, humidity, light lux, bulb status, operating mode) to Firebase Realtime Database. The web dashboard provides dynamic time-series charts and allows users to export all historical logs as a downloadable CSV spreadsheet.

02

Concepts (In My Own Words)

// FORGE RULE #1: OWN WORDS > COPY-PASTE

Closed-Loop Automation & Hysteresis

In a closed-loop system, sensor feedback automatically drives actuator outputs. To prevent relay chatter (rapid ON/OFF flickering when sensor readings fluctuate around a single threshold point), we implement a hysteresis band: the light turns ON below 1400 raw ADC, but requires the room to brighten beyond 1700 raw ADC before switching OFF.

Time-Series Database Logging

Instead of constantly overwriting a single /current node, time-series logging records every reading as an immutable, timestamped event under a chronological log tree (e.g. /logs/2026-10-08/1728362400). This enables historical trend analysis and auditing.

Client-Side Data Export (Blob & CSV)

Rather than relying on a heavy backend server to generate spreadsheets, modern browsers can serialize JSON records into RFC 4180 Comma Separated Values (CSV), bundle the string into an in-memory Blob object, and trigger a native file download using a temporary anchor element.

Wiring & Sensor Calibration

// PIN CONNECTIONS & THRESHOLDS
Signal ESP32 Pin Sensor / Actuator Operating Range / Threshold
Climate Data GPIO 4 DHT11 Data Line 20°C to 45°C / 30% to 90% RH
Light Analog Level GPIO 34 LDR Voltage Divider Midpoint Threshold ON: < 1400 | Threshold OFF: > 1700
Relay Drive GPIO 18 Relay Input (IN) Active HIGH (+3.3V trigger)

LDR Threshold Calibration Procedure:

1. Full Ambient Light (Daylight): LDR resistance drops to ~5kΩ; measured ADC voltage is ~2.8V (raw ADC value: ~3200–3500).
2. Dusk / Shaded Conditions: Measured ADC value hovers around 1500–1600.
3. Darkness (Night / Hand Covered): LDR resistance exceeds 500kΩ; measured ADC value drops below 1000.
4. Hysteresis Logic: Trigger ON when Light < 1400; Trigger OFF when Light > 1700. The 300-point deadband eliminates false toggles from slight shadows.

Implementation & Source Code

// AUTOMATION & LOGGING FIRMWARE
ESP32_Capstone_Automation_Logging.ino 
#include <WiFi.h>
#include <FirebaseESP32.h>
#include <DHT.h>
#include "time.h"

#define WIFI_SSID     "YOUR_WIFI_SSID"
#define WIFI_PASS     "YOUR_WIFI_PASSWORD"
#define FIREBASE_HOST "YOUR_PROJECT.firebaseio.com"
#define FIREBASE_AUTH "YOUR_DATABASE_SECRET"

#define DHTPIN 4
#define LDRPIN 34
#define RELAYPIN 18

const int THRESHOLD_DARK  = 1400;
const int THRESHOLD_LIGHT = 1700;

DHT dht(DHTPIN, DHT11);
FirebaseData fbdo;
FirebaseAuth auth;
FirebaseConfig config;

unsigned long lastLogTime = 0;
bool currentBulbState = false;
String currentMode = "AUTOMATIC";

void setup() {
  Serial.begin(115200);
  pinMode(RELAYPIN, OUTPUT);
  digitalWrite(RELAYPIN, LOW);
  dht.begin();

  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) { delay(500); }
  
  configTime(19800, 0, "pool.ntp.org"); // IST (UTC + 5:30)

  config.host = FIREBASE_HOST;
  config.signer.tokens.legacy_token = FIREBASE_AUTH;
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true);
}

void loop() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  int ldr = analogRead(LDRPIN);

  // 1. Retrieve Current Mode from Firebase
  if (Firebase.getString(fbdo, "/iot_system/system_state/mode")) {
    currentMode = fbdo.stringData();
  }

  // 2. Execute Control Logic
  if (currentMode == "AUTOMATIC") {
    if (ldr < THRESHOLD_DARK && !currentBulbState) {
      currentBulbState = true;
      digitalWrite(RELAYPIN, HIGH);
      Firebase.setBool(fbdo, "/iot_system/system_state/bulb_state", true);
    } else if (ldr > THRESHOLD_LIGHT && currentBulbState) {
      currentBulbState = false;
      digitalWrite(RELAYPIN, LOW);
      Firebase.setBool(fbdo, "/iot_system/system_state/bulb_state", false);
    }
  } else { // MANUAL MODE
    if (Firebase.getBool(fbdo, "/iot_system/system_state/bulb_state")) {
      currentBulbState = fbdo.boolData();
      digitalWrite(RELAYPIN, currentBulbState ? HIGH : LOW);
    }
  }

  // 3. Periodic Historical Logging (Every 30 seconds)
  if (millis() - lastLogTime > 30000) {
    lastLogTime = millis();
    FirebaseJson json;
    json.set("temperature", t);
    json.set("humidity", h);
    json.set("light_level", ldr);
    json.set("bulb_state", currentBulbState ? "ON" : "OFF");
    json.set("mode", currentMode);
    
    Firebase.pushJSON(fbdo, "/iot_system/historical_logs", json);
  }
}

Configuration & CSV Export Engine

// FRONTEND EXPORT LOGIC
dashboard_export.js (Client CSV Generator) 
function exportTelemetryToCSV(records) {
  let csv = "Timestamp,Temperature_C,Humidity_Pct,Light_Raw,Bulb_State,Mode\n";
  
  for (const key in records) {
    const item = records[key];
    csv += `"${item.timestamp}",${item.temperature},${item.humidity},${item.light_level},"${item.bulb_state}","${item.mode}"\n`;
  }

  const blob = new Blob([csv], { type: 'text/csv;charset=utf-8;' });
  const url = URL.createObjectURL(blob);
  const link = document.createElement('a');
  link.href = url;
  link.download = `iot_forge_telemetry_${Date.now()}.csv`;
  link.click();
  URL.revokeObjectURL(url);
}

Challenges, Limitations & Future Scope

// FORGE RULE #2: SHOW THE FAILURE, NOT JUST FIX
FAILURE #1
Relay Rapid Oscillations (Chatter) Around Single Threshold
Root Cause Analysis

When room light hovered right at the static threshold (1500), subtle atmospheric shadows and sensor noise caused the ADC reading to bounce above and below 1500 multiple times a second, switching the relay noisily and stressing contacts.

Solution Implemented

Programmed dual asymmetric hysteresis limits: Activated relay at < 1400 ADC, deactivated at > 1700 ADC. This created a solid 300-point buffer zone that completely eliminated false switching.

SYSTEM LIMITATIONS
Current Constraints & Future Improvements
Current Prototype Limitations

The DHT11 sensor is restricted to 0°C–50°C with ±2°C accuracy, and free-tier Firebase JSON tree size must be manually culled after 100,000 data nodes to prevent download lag.

Future Scope & Roadmap

Upgrade to an industrial I2C BME280 sensor (measuring barometric pressure in addition to temp/humidity), implement edge SQLite logging on micro-SD card for offline redundancy, and add OTA (Over-The-Air) Wi-Fi firmware updates.
