Core Objective & Architecture Overview

// THE BIG PICTURE
🎯

Embedded Micro-Server Paradigm

  • Transforms the ESP32 into a self-contained local web server hosting responsive HTML directly from program flash.
  • Zero external dependency on internet, AWS, or third-party cloud brokers; functions flawlessly in isolated air-gapped networks.
  • Forms the core baseline for commercial edge IoT devices (e.g., smart plugs, localized device gateways, and industrial HMIs).
⚙️

Request Routing & GPIO Dispatch

  • Endpoint GET /: Returns main control console with large styled touch-friendly ON and OFF buttons.
  • Endpoint GET /on: Executes digitalWrite(LED_PIN, HIGH), illuminates the onboard blue LED, and returns confirmation with Back link.
  • Endpoint GET /off: Executes digitalWrite(LED_PIN, LOW), de-energizes the blue LED, and renders state feedback.

Core Firmware Architecture

// ARDUINO C++ SOURCE: task1esp32.ino
task1esp32.ino 
#include <WiFi.h>
#include <WebServer.h>

const char* ssid     = "protosem";
const char* password = "Proto#123";

#define LED_PIN 2

WebServer server(80);

void handleRoot()
{
  String html = R"rawliteral(
<!DOCTYPE html>
<html>
<head>
  <title>ESP32 LED Control</title>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <style>
    body { font-family: Arial; text-align: center; margin-top: 80px; }
    h1 { font-size: 35px; }
    button { width: 150px; height: 60px; font-size: 22px; margin: 15px; cursor: pointer; }
  </style>
</head>
<body>
  <h1>ESP32 LED Control</h1>
  <a href="/on"><button>ON</button></a>
  <a href="/off"><button>OFF</button></a>
</body>
</html>
)rawliteral";

  server.send(200, "text/html", html);
}

void handleLEDOn()
{
  digitalWrite(LED_PIN, HIGH);
  server.send(200, "text/html", "<h1>LED is ON</h1><a href='/'>Back</a>");
}

void handleLEDOff()
{
  digitalWrite(LED_PIN, LOW);
  server.send(200, "text/html", "<h1>LED is OFF</h1><a href='/'>Back</a>");
}

void setup()
{
  Serial.begin(115200);

  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);

  // Connect to Wi-Fi
  WiFi.begin(ssid, password);
  Serial.print("Connecting to WiFi");

  while (WiFi.status() != WL_CONNECTED)
  {
    delay(500);
    Serial.print(".");
  }

  Serial.println();
  Serial.println("WiFi connected!");

  Serial.print("ESP32 IP address: ");
  Serial.println(WiFi.localIP());

  // Web server routes
  server.on("/", handleRoot);
  server.on("/on", handleLEDOn);
  server.on("/off", handleLEDOff);

  server.begin();
  Serial.println("Web server started!");
}

void loop()
{
  server.handleClient();
}
06

Debugging Insights & Engineering Takeaways

// PRACTICAL BENCH LOG
⚠️

The Challenge: Mobile Browser Favicon Requests

  • Modern smartphones running Chrome or Safari automatically send an immediate auxiliary request to /favicon.ico immediately following the main document.
  • In naive custom TCP stream socket parsers, any unexpected URI string can cause unintended state changes or client buffer hangs.
✅

The Engineering Solution: Explicit Routing via WebServer

  • Leveraging ESP32's native WebServer.h library with strict route registrations (server.on("/", ...), server.on("/on", ...), server.on("/off", ...)).
  • Unregistered auxiliary requests like /favicon.ico are cleanly dropped with 404 without altering GPIO state or blocking the loop.

01

Why MQTT Beats HTTP for IoT Devices

// ARCHITECTURE COMPARISON

❌ Traditional HTTP Model

  • Heavy Overhead: Each request carries 500–1000 bytes of repetitive header strings.
  • Polling Required: The ESP32 must constantly ask "is there data?" every few seconds, draining power.
  • High Latency: Full TCP handshake + teardown on every single message.

✅ Lightweight MQTT Model

  • Tiny 2-Byte Header: Optimized for low-bandwidth cellular & battery IoT nodes.
  • Instant Push Notification: Cloud broker pushes values to the ESP32 the exact millisecond they change.
  • Persistent Connection: Single TCP socket remains open; continuous streaming.

// CODE & RESILIENCE
esp32_adafruit_mqtt.ino 
#include <Adafruit_MQTT.h>
#include <Adafruit_MQTT_Client.h>

WiFiClient client;
Adafruit_MQTT_Client mqtt(&client, "io.adafruit.com", 1883, "night07owl", "AIO_KEY");
Adafruit_MQTT_Publish tempFeed = Adafruit_MQTT_Publish(&mqtt, "night07owl/feeds/temp");

void MQTT_connect() {
  if (mqtt.connected()) return;
  while (mqtt.connect() != 0) { delay(2000); } // Reconnect loop
}

void loop() {
  MQTT_connect();
  float sensorVal = analogRead(34) * (3.3 / 4095.0) * 10.0;
  tempFeed.publish(sensorVal);
  mqtt.processPackets(1000);
  mqtt.ping(); // Keep-alive heartbeat avoids disconnects
  delay(5000);
}
⚠️

The Bug: Periodic 60-Second Socket Dropping

  • Adafruit IO terminates connections if no message is received within the 60-second Keep-Alive window.
  • When the sensor loop was set to update every 90 seconds to save data, the broker forcibly killed the socket.
✅

The Engineering Fix

  • Introduced mqtt.ping() every 30 seconds to maintain the active session without sending unnecessary payload data.
  • Built an automatic reconnect recovery loop so dropped Wi-Fi immediately self-heals without device restart.

#include <HTTPClient.h>

const char* iftttUrl = "https://maker.ifttt.com/trigger/temp_alert/with/key/YOUR_KEY";
unsigned long lastTrigger = 0;
const unsigned long cooldownMs = 120000; // 2-minute spam lock

void sendIftttAlert(float temp) {
  if (millis() - lastTrigger < cooldownMs) return; // Cooldown active
  
  HTTPClient http;
  http.begin(iftttUrl);
  http.addHeader("Content-Type", "application/json");
  String payload = "{\"value1\":\"" + String(temp) + " C\",\"value2\":\"Forge Station 03\"}";
  int httpCode = http.POST(payload);
  http.end();
  
  lastTrigger = millis();
}

01

Understanding Software Hysteresis & Anti-Chatter

// CONTROL THEORY IN PLAIN ENGLISH
⚠️

The Relay Chatter Problem

  • If a single threshold is used (e.g., Light < 1500), sensor noise causes the reading to bounce between 1499 and 1501.
  • The mechanical relay clicks ON and OFF 10 times per second, causing electrical arcing and rapid component failure!
🛡️

The Two-Threshold Deadband Fix

  • Turn-ON Threshold (1200): Light must plunge below 1200 before the lamp turns ON.
  • Turn-OFF Threshold (1500): Light must rise all the way past 1500 before turning OFF.
  • 300-Point Deadband: Any noise within 1200–1500 is completely ignored; rock-solid stability!
